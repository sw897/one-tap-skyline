## 目标与现有基础

把当前规则排列的城市原型完善为明亮、现代、有街道与滨水景观的三维城市。城市占主画面，排行榜、最新动态和真实二维码辅助展示；支持放大、拖动、定位楼体与自动街区漫游。手机仍只玩游戏、装饰及查看自己的楼，所有更新来自已成功提交的有效成绩，保留B/60秒、连击仅反馈和同一楼体/层高规则。

## 场景与楼体表现

推荐“明亮滨水现代城市”：浅色街道、路沿和标线、行道树、公共广场/公园、滨水步道与简化桥梁；通过日光、轻雾、接触阴影和层次建立城市感。先用代码几何、实例化景物和通用材质，不复制私有概念图或引入未经审核的模型/品牌资产，不做交通模拟或大型写实城市工程。

玩家楼继续用同一TowerModel/buildTower，逐层裁切、坐标、宽深、基座、层高和照片立面一致。可细化统一的窗线/边缘和材质语言，不能为了天际线抬高低分楼、替换另一套城市楼型、拼接前后两局。全景与近景通过相机取景适配真实高低，而非单独缩放业务高度。

场景道路与公共设施围绕既有地块组织，避免占用玩家位置。街区按现有地块分组，不假定四区人数均分。建议在外围增加少量低矮、中性公共建筑，作为景观且不占玩家地块、人数或排名，没有玩家署名/照片。空城保留道路、水岸和公共景观，明确“今日0栋玩家建筑”；连接失败时显示等待连接，不能用模拟玩家/成绩填充真实城市。设计示意图中的虚构楼层、人数和二维码不作指标。

## 镜头、布局与找楼

大屏入口沿用/?mode=display&view=city。推荐城市视区约72%宽、侧栏约28%；相机按实际城市视区与最高楼包围盒取景，预留标签/控件安全区。侧栏含二维码、真实楼数、前10名和最近5–8条动态；镜头移动不移动二维码。标签只保留选中楼、近期事件或当前街区重点楼，减少重叠。

大屏单独使用透视相机和受限OrbitControls：拖动环绕、滚轮/按钮放大、辅助平移；限制距离、俯仰和目标范围，保留“回全景”。游戏/个人作品保持原相机操作。现有锁定Three.js包包含该控制器；[官方相机文档](https://threejs.org/docs/pages/PerspectiveCamera.html)、[官方控制器文档](https://threejs.org/docs/pages/OrbitControls.html)支持这些能力，具体构图仍待可运行候选验证。

推荐默认慢速巡游“全景→有玩家的街区→全景”，街区停留约10秒、转场约2秒；手动操作立即接管，空闲20秒后恢复，也可暂停自动。点击排行/标签或按署名、地块号搜索，可聚焦当前完整楼体及照片；新最佳后继续跟随同一楼ID，取景按新几何计算。手机可显示自己的街区/地块号，不恢复总览或全城轮询，也不远程抢占大屏镜头。以上时间、镜头边界、标签数量均为可调初值。

二维码在浏览器本地编码，使用真实站点的手机入口，稳定白底展示并附短链接；不调用外部二维码图片服务、不使用概念图二维码。正式城与测试城入口明确区分，待P6再切最终域名。没有真实扫码结果时只记录二维码已生成，不宣称投屏扫码通过。

## 真实事件与同步边界

| 有效提交结果 | 大屏行为 |
| --- | --- |
| 首次入城 | 原地出现完整新楼，简短欢迎与地块提示 |
| 严格超过个人最佳 | 用完整新局几何原地更新并长高，提示旧层数→新层数 |
| 严格超过提交前全场最高 | 优先显示全场新纪录与短暂高亮；同次提交只播一个主要提示 |
| 空城首楼/并列最高 | 首楼按首次入城；并列不算全场新纪录，名次沿用1、1、3规则 |
| 低/同分、重复、无效或满城未入城 | 不生成增长/纪录事件，保留既有真实状态 |
| 换图、撤回或到期 | 更新/移除贴图，不触发成绩增长或纪录播报 |

建议在既有成绩条件提交的同一D1批处理中追加有界city_events记录，捕获提交前最高分、事件ID/runId、城市epoch、版本、目标楼、前后层数及服务器时间，避免靠两次快照猜测中间纪录。全场判定必须在事务内取值；幂等重试不重复写事件。仅追加必要schema，不改已应用SQL，不新增身份恢复、管理角色或备份/兼容迁移工具。[D1批处理文档](https://developers.cloudflare.com/d1/worker-api/d1-database/#batch)说明批处理事务/失败回滚；这是拟采用的实现方式，尚未测试。

大屏沿用约3秒轮询，在all-city读取中附带有界事件游标/结果，尽量同批读取一致的城市、排名与事件；手机own范围不接收事件流。首次打开只显示当前城和近期动态，不逐个重播旧纪录。建议每城保留当日最近200条事件、每次最多40条；游标缺口/断线恢复以最新快照追平，旧动态不连续抢镜。

动画按楼ID并行管理；最新动态保留真实发生时间，主画面最多一个提示/聚焦，待播队列最多20条，同楼合并到最新最佳。过时事件不把楼变回旧几何；展示前校验当前epoch、目标楼和bestRunId。全场提示优先，手动查看期间先在侧栏提示；不会每次提交都强制镜头跳转。事件排队等待与数据同步时延分开记录。

照片仍按当前资产/装饰版本读取，不复制图片到事件记录；远景仅缩略图，选中楼才用大图，撤回/到期后释放纹理。网络异常保留上次有效城及更新时间；首次无数据、恢复、后台/前台和重试有明确状态。午夜清空新增事件表，并清理客户端队列、高亮、选择和旧纹理，重新回到新日景观；epoch/版本/请求世代保护迟到响应。保留现有00:00任务，不新建重复任务，不增加逐帧观战或相机同步服务。

## 实施顺序

1. 审核下方三项决定，锁定场景基调、自动/手动行为及大屏设备基线；记录P4仍未验证事项。
2. 分离只读大屏启动/UI和城市相机；复用原楼体/照片引擎，先完成空城与少量真实楼也成立的道路、水岸和公共景观。
3. 加入受限漫游、稳定街区巡游、标签、搜索/定位与真实二维码；保持手机流程和输入边界。
4. 在服务端增加事务事件，接入快照/游标、多个楼的增长、高亮与队列；照片更新不混入成绩事件。
5. 完成断线/后台恢复、午夜事件清理与迟到数据保护；采用实例化景物、有限标签/纹理及可调画质，延续60栋/20并发基线。
6. 完成必要编译构建和发布准备，审查实际待推提交/全历史/tag/资产；同一Sites/public范围发布p5-event-screen-preview候选，交用户手工体验。最终p5-event-screen标签与正式验收结果待全部开发后确定；本轮不执行P6 Docker/SSH。

## 需要用户决定

1. **场景背景**：推荐明亮滨水城市，允许少量不计成绩的低矮公共建筑，让空城仍有现代城市感；也可只保留道路、公园和水岸。
2. **展示方式**：推荐默认慢速自动街区巡游，同时可手动接管、暂停，空闲20秒恢复；也可默认静止、由主持人控制。事件默认侧栏提示，自动巡游时全场纪录可短暂聚焦。
3. **现场设备**：规模沿用已确认的60栋/20并发；请补充实际投屏电脑、浏览器与屏幕分辨率。设备未知时暂按16:9 1920×1080电脑Chrome做可调候选，真实性能和扫码距离等最终现场验证。
