# 阶段与重要修复记录模板

每个阶段交付和重要修复都使用本模板。完整原始记录保存到仓库外受控目录，公开版本只保留经审阅的事实摘要。已授权的策划会话接收整理后的材料；目标标识与授权原文保存在私有台账。

## 记录内容

| 字段 | 应填写的事实 |
| --- | --- |
| 标题与状态 | 阶段/修复目标、用户日期与时区；待审、进行中、已交付或仍有缺项。 |
| 需求与决定 | 实际要求、批准范围、关键选择及原因。原文私存，公开写中性摘要。 |
| 做了什么 | 完成的功能、修复和范围；区分规划与实际实现。 |
| 版本对应 | 应用完整 commit SHA、tag、文档 commit、Sites 版本/部署结果/实际 URL；不以预期地址代替发布成功。 |
| 测试与结果 | 实际命令、环境、配置、输入/操作、通过或失败、日志位置。继承旧测试要说明源码未变，不能写成重新执行。 |
| 问题与修改 | 实际症状、已证实原因或待验证推断、修改、相关 commit 和修复后验证。保留失败原件。 |
| 尚未验证 | 未执行、缺失、受阻或仅有用户反馈的项目；说明缺什么，不补造数据。 |
| 证据索引 | 截图、录屏、日志、反馈、公开推送审查的证据编号和私有路径；保存哈希、记录时间和版本关联。 |
| 同步结果 | 经审阅的同步正文、目的地、发送结果、读回确认和内容哈希；失败或未读回要明确标注。 |

## 执行与更新

1. 从实际 Git、部署、测试和反馈取事实，引用原始证据；测试前的工作区可关联最终修复提交，但注明当时尚未提交。重要修复单独提交，尽量保留安全可复现的修复前 Git 引用；未分提交的历史故障如实注明，不补造 SHA。
2. 成功、失败、手机尺寸模拟、真实手机和用户反馈分别标注。旧记录保留原时间状态，新结论追加并更新当前索引。
3. 审查公开文档与每次 public 推送的实际范围、历史对象和 tag。原始交接包、未脱敏对话、客户素材、个人照片和凭据不进入公共仓库。
4. 同步整理后的记录到用户已授权的会话，读回确认后记为完成。未来阶段/重要修复沿用同一方法，不据归档消息自行启动下一阶段。

重要修复包括影响主要操作、计分/楼体一致性、真机使用、数据或发布访问的问题。纯排版文字修订可用简短条目，保留对应文档提交。
