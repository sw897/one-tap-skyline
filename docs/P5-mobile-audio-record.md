## 反馈、原因边界与实现

用户反馈 iPhone 的微信内置浏览器与 Chrome 中，音效开关为开，但落层和试听均无声；进一步反馈关闭系统静音后仍无声。因此系统静音不能作为本次已证实的根因。未取得这台设备的音频内部状态或实际输出录音，不将浏览器兼容推断记为根因复现。

旧版仅通过 Web Audio 发声，恢复失败被忽略，试听还会在上下文已运行时继续等待 resume Promise。修订为 iPhone/iPad 使用同一音高、包络和连击音调生成的短 PCM WAV，通过媒体元素播放；保留其它浏览器的 Web Audio。使用4个有界媒体声部，不持续播放背景音；触摸结束可重试最近被拦截的落层播放，过期不补播。静音、后台和退出时停止播放与待重试声音。试听增加有界启动结果提示，“已启动”仅指播放请求成功，不代表设备扬声器已验证出声。

计时、B/60秒、计分、楼体/照片、展示竞争、每日重置和扫码资格未修改；音频启动不阻塞开局或提交。候选继承已有P6文档审订，未启动P6运行实现。
