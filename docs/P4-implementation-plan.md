## 已确认的范围

- 照片保存后即时公开到城市与大屏，不设先审后显或审核后台；选择照片前说明公开展示，保留显式跳过和提前撤回。
- 匿名身份沿用已有同浏览器cookie，不做跨端恢复，也不建立独立照片所有权/角色权限系统。既有cookie用于确定“我的楼”这一业务目标。
- 照片最多保留24小时、未保存草稿4小时失效；用户已确认每天北京时间00:00清空全部照片/草稿。
- 用户随后扩大为每天北京时间00:00重置整个游戏：清空正式和共享测试城市的楼体、成绩、排行榜、匿名玩家、局次、照片、草稿与限频记录。下一天重新匿名登记、从空城市开始；系统只保留防重复重置的技术标记。
- 不开发图像备份/恢复、历史照片导入或兼容迁移工具。不为此做旧数据转换；照片功能所需新表通过必要的追加schema创建，已应用SQL保持原样。
- 本轮不执行阶段验收、浏览器完整流程、跨设备、压力或真机测试。保留必要类型检查、生产构建、部署与定时任务准备；用户先手工试玩，再进入下一阶段设计和实施，所有功能完成后统一验收。

## 功能顺序与边界

手机结算可选图、拖动/缩放裁切和预览，然后提交成绩；成绩成功后独立保存贴纸，失败不让楼或成绩丢失。首次/新最佳可保存本次选图；低分/同分保留原图，用户可明确为最佳楼更新贴纸。新最佳沿用已保存照片，换图或撤回只更新装饰，不改变几何、层数、名次和地块。

“我的楼”提供装饰、换图、重试和撤回入口。照片保存后即时公开，原始图片不上传；服务端重新编码仅存成品和缩略图，过期/撤回新请求拒绝读取。客户端照片到期即移除，不因文件任务迟到而继续显示。原图只在手机临时处理，关闭页面会丢弃本地草稿。

游玩、结算、我的楼和大屏仍使用统一TowerModel/buildTower。正面下部最多三层分段采样同一照片，遵循实际X/Z退台，不跨悬空位置或另造装饰楼体；大屏远景用缩略图，定位楼时用大图。

沿用B/60秒、连击仅反馈、同浏览器当天固定楼与地块；手机不恢复全城轮询，大屏约3秒更新。完整现代城市景观、道路层次及自然漫游仍待P5设计；Docker/SSH仍P6。

## 实现与每日任务

1. 同一Git/Sites项目增加BUCKET文件绑定和照片表，沿用DB及原游戏引擎。追加schema只创建照片关联与每日标记，不复制源码或重写已应用迁移。
2. 前端选择JPEG/PNG/WebP，裁切为512×768 JPEG；建议源图20MiB/24MP，上传512KiB上限，成品256KiB与128×192缩略图。HEIC及实际手机选择能力由用户手工反馈，不宣称已兼容。
3. 新照片接口独立于成绩时序JSON，复用既有匿名会话业务定位；草稿/公开关联分开，重试、换图、撤回通过装饰版本更新。图片本体和原文件名不进入城市JSON或Git。
4. 用服务器时间判定北京时间日期，CAS标记保证一天最多清一次；按外键顺序原子清空游戏表并生成新城市epoch。每次游戏API先检查日期，午夜后不能继续提交旧局或读取旧成绩。客户端检测午夜/新epoch重新加载，重新匿名登记。
5. 图片key含服务器日期。定时任务清空上一日及更早文件；晚到任务保留新一天图片。撤回先取消公开关联再删文件，删除失败留待重试。用户草稿4小时失效，午夜一并删除。
6. 发布同一public站点后配置Sites云任务，Asia/Shanghai每天00:00调用服务器固定的reset-due接口；调用不接受客户端日期、城市、对象key或强制清库选项。记录任务是否保存、接口调用结果与首次实际定时执行，三者不能互相替代。

文件存储采用R2 Worker API；数据表用D1批处理，文件删除与SQL并非一个事务，故到期禁读和后续物理清理分开。[D1批处理](https://developers.cloudflare.com/d1/worker-api/d1-database/#batch)、[R2 Worker API](https://developers.cloudflare.com/r2/api/workers/workers-api-reference/)。
