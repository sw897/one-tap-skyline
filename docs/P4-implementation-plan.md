## 体验范围与推荐行为

结算页保留“选择照片”和“跳过”并列入口；可在手机本地选择、拖动裁切、缩放、查看贴在当前作品上的预览。开始游戏前不要求照片、署名或登录。零层局可预览，但无有效城市楼时不上传。已有楼可从“我的楼”进入更换/移除贴纸。

点击提交先走既有成绩验证，再处理选填贴纸。成绩已成功、照片尚未保存或审核时分别提示状态；上传失败可重试或跳过，不重新提交成绩、不丢楼。推荐行为如下：

| 情景 | 楼体与成绩 | 照片 |
| --- | --- | --- |
| 首次有效入城 | 分配稳定地块，保存完整有效楼体 | 可继续上传/绑定已预览照片，也可无照片完成 |
| 低分或同分 | 完整最佳楼、地块、颜色、署名与名次保持 | 保留原照片；本局新选择不自动替换，提示可明确“为最佳楼更新贴纸” |
| 新个人最佳 | 同地块替换完整新局几何并长高 | 沿用原照片；明确保存新图后才替换 |
| 单独换图/移除 | 层数、几何、最佳局、排名、地块与署名不变 | 单独装饰操作，只触发装饰更新；不播放破纪录长高 |
| 上传/审核失败 | 已提交的成绩保留 | 原公开照片继续保留，失败草稿不公开；用户可撤回 |

跳过表示不保存本次照片草稿，已有照片保持；移除已有照片使用独立明确入口。照片针对同城市的那栋楼，测试城市照片不会随身份出现在正式城市。

## 立面与图片处理

推荐最小方案为一张照片、一个正面贴图区、固定竖向裁切框；先复用下部最多三层的预留立面。退台处按真实层面分段，连续采样同一张图片，不跨越悬空退台、不重复三张头像。短楼、窄楼按可用墙面缩放并保留可见边框；照片不遮挡移动层落点，不增加建筑高度。结算、“我的楼”和城市调用同一立面布局/纹理规则；变高后重新按新几何定位，不拼接旧局楼层。

手机本地先支持JPEG/PNG/WebP选择和裁切，产出规范JPEG；相册HEIC、横向照片方向和微信内置浏览器文件选择单独真机验证，未通过时明确提示使用可解码格式。取消选择、解码失败和文件过大都可继续无照片流程。

建议技术预算为源图不超过20MiB/24MP；上传成品不超过512KiB，服务器校验真实格式、尺寸和解码预算后重新编码，只保留约512×768、至多256KiB的成品及128×192、至多32KiB的缩略图。预算待P4实测调整；不把浏览器MIME/扩展名当证明，不接受SVG、HTML、动画或任意外链。服务器成品移除EXIF/GPS等元数据，原图仅留手机；重新裁切需重新选原图。

首个实施步骤验证兼容Workers的JS/WASM JPEG解码和重编码，明确像素/内存/CPU边界；不能因本地Miniflare依赖含sharp就宣称线上可用。实现前不安装库或启用额外收费服务；若规范化处理线上无法通过，保持真实照片入口关闭并报告具体阻塞。

## 存储与同步契约

D1保存资产归属、状态、尺寸、内容hash、到期时间和楼体装饰关联；R2只存规范图片与缩略图。沿用DB，审核后才增加逻辑BUCKET绑定，由Sites配置资源。通过Worker同源媒体接口读取；不公开桶、不把对象key、照片字节或base64放入城市快照。

成绩接口与时序规则保持独立。照片上传使用专门的有界二进制接口，不能塞进现有64KiB成绩JSON。服务端通过cookie和城市查自己的楼，不相信客户端playerId；绑定、换图、删除均检查归属、同源Origin、类型与速率。建议每身份10分钟内5次新图和有限待处理配额，配合城市总容量上限；失败和合法重试不计为新资产。

推荐新增photo_assets与building_facades两张表，装饰附着稳定楼身份而非bestRunId。草稿/待审核与已公开关联分开；原照片在新图获准前继续有效。资产ID、幂等操作ID与预期装饰版本配合，重复正文返回同回执，不同正文或陈旧换图409拒绝。删除/审核拒绝后，旧上传完成或迟到审核不能复活图片。

推断与技术决策：D1批处理事务覆盖SQL，R2写入是独立操作，因此采用状态与补偿流程，而非承诺跨存储原子事务：登记草稿→规范化并写R2→标记待审核→批准后在D1原子切换关联、增加装饰版本/城市revision；任一步失败保持旧公开照片，未关联对象进入有界重试清理。[D1批处理](https://developers.cloudflare.com/d1/worker-api/d1-database/#batch)、[R2 Worker API](https://developers.cloudflare.com/r2/api/workers/workers-api-reference/)。

照片公开、更换、撤回或隐藏增加城市revision；单纯草稿不更新公共城市。装饰版本单独标明，低分/同分成绩仍不改revision。修改SharedCityRepository.apply当前按bestRunId复用旧对象的判断及渲染同步，使装饰变化可见、几何仍复用；旧响应、旧图片加载和重复通知不得覆盖新图或恢复已删除照片。

手机保持自身视图，不恢复全城轮询；照片保存及主动查看取自身数据。大屏沿用约3秒更新，远景只请求缩略图，定位某楼才加载大图；纹理按资产版本缓存并释放，避免60楼全部加载大尺寸照片。

## 公开展示与管理

推荐保留现有免登录体验范围。照片提交前单独明确告知：批准后会显示在任何知道站点链接的人可访问的城市与大屏；由用户选择有权展示的图片并主动确认。P3对成绩/署名的公开授权不等于照片开放授权，本计划审核须同时确认照片范围。

推荐正式初期先审后显：玩家可看到自己的待审核状态/预览，大屏只看到已通过图片；提供最小审核、拒绝、立即隐藏与玩家撤回能力，不做完整运营后台或AI识别。管理操作仅限已验证的平台登录身份及私有管理员名单；管理员身份若无法验证，不开放匿名管理路由。审核者须在开放真实收集前确定，未安排审核时只运行已审核测试素材。

媒体读取检查当前公开关联、状态与期限，使用no-store；不开放可绕过撤回的R2直链。换图后旧图接口、撤回/隐藏后图片接口的新请求立即拒绝，大屏下一次更新移除纹理。R2自身删除强一致，但启用外部缓存会改变可见效果，因此P4先避免长缓存。[R2缓存与一致性](https://developers.cloudflare.com/r2/reference/consistency/)。

建议默认照片保留30天，到期禁读，维护工具执行物理清理；待处理草稿24小时到期。玩家可提前删除，管理员可处理已失去cookie的撤回请求。清理工具先dry-run、列出精确资产及状态，再由受控执行删除；对失败重试记录结果。正式开放前验证到期清理可持续执行的路径和负责人，不在规划时预设已有自动调度。图片备份也按批准期限淘汰，恢复时应用撤回记录，不能复活删除照片；公开图片已被另存或截屏无法收回，提交提示简短说明这一点。

## 数据兼容与迁移

追加schema-only迁移，不修改已应用SQL、snapshot/journal，不把照片/回填数据塞进迁移。旧楼装饰默认为无，保留全部P3身份、地块、颜色、署名、最佳局、楼层几何与城市epoch；只为实际装饰变更增加revision。

当前私有导出仅含四张持久表、格式version1。P4增加version2，保留读取version1的兼容转换；图片字节和清单需一起导出，逐项关联资产ID/hash/类型/状态/期限。完整数据含匿名凭证哈希与照片，只在仓库外私存。

在隔离D1/R2测试P3数据升级、成品与缩略图完整导出、空库/空桶恢复，核对几何与贴图hash；缺文件、损坏、已撤回、到期资产必须拒绝公开或降级无照片，不伪造成功。备份/恢复时冻结照片写入并记录截点；先恢复对象，再启用引用，失败清理临时对象。精确CLI/权限与Sites线上导出路径需实测，当前本地工具成功不代表能导出托管资源。

关闭照片开关后可回退兼容应用；平台失败可能已应用schema，须分别核对应用、schema和文件。P6的Docker存储适配及线上搬迁不在P4完成。

## 实施顺序

1. 审核下方三个产品决定；补真实照片开放、审核者和清理责任。先关闭正式照片写入，以test-mobile/独立资源前缀和中性测试图验证R2、Worker规范化、媒体读取与删除；确认备份/恢复权限。能力失败先解决或报告，不用本地通过替代线上通过。
2. 增加可选装饰协议、D1追加迁移、文件存储适配和幂等/版本规则；测试现有数据升级和权限。固定有效成绩规则及公共读写基线。
3. 完成手机本地选择/裁切/预览/跳过，再接上传状态、明确换图/删除与审核状态；只保存成功成绩对应的自身楼。失败可继续玩。
4. 给同一楼体生成器加入贴图，在个人楼和大屏同步；处理退台、短楼、比例、迟到纹理和释放，图片更新不触发长高。
5. 增加受控审核/隐藏、草稿补偿/到期清理及version2导出恢复；运行下方专项与P3回归。
6. 保留同项目/同public受众，审查源码、历史/tag、构建和实际页面；先隔离线上验证，再开放审核确认的真实照片范围。形成p4-photo-facade-preview候选供iPhone复测；满足阶段验收再打p4-photo-facade，不用计划文件宣称已交付。

## 需要用户决定

1. **照片展示与审核**：推荐沿用链接公开访问，玩家明确确认后上传，正式初期先审后显；由你或指定审核者管理。若希望即时公开，需要明确选择并保留隐藏/撤回路径。
2. **匿名身份边界**：推荐继续同浏览器cookie管理自己的楼和照片；跨浏览器、换设备、清cookie或30天过期后不能自行认领原楼。若必须跨端恢复，先另行细化并审核身份方案。
3. **照片期限**：推荐成品及缩略图保留30天、草稿24小时，允许提前撤回；维护者执行到期清理。确认这一期限，或指定活动结束后统一删除的时间/维护者。
