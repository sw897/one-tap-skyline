# P4 照片与每日游戏重置开发记录

2026-10-12，Asia/Shanghai。状态：P4代码实现完成，准备发布可试玩候选；用户手工测试与正式验收尚未发生。以下是审阅后的事实摘要，完整原文、实际输出和平台回执在仓库外私存。

## 真实要求与决定

用户批准即时公开照片、同浏览器匿名身份无需跨端恢复、照片最多24小时/草稿4小时、允许提前撤回。用户明确选择每天北京时间00:00清空全部照片草稿，随后进一步要求00:00重置整个游戏、清空所有游戏数据。本实现按最后一项清空成绩、楼体、排名、玩家、局次、照片草稿及限频记录，正式/共享测试城市一起重新开始；源码、Git与开发证据不在游戏数据范围内。

用户取消图像备份恢复、独立所有权系统及兼容迁移工作，并要求本阶段不执行验收，由用户先手工测试，再推进后续阶段设计/实施，全部完成后统一验收。保留实际编译、构建和发布准备，不把未执行的功能验收写成通过。

## 做了什么

- 接入可选照片选择、拖动/缩放裁切、统一幕墙预览、跳过与公开确认；成绩入城成功后独立保存照片，失败可从我的楼重试，已有成绩不因此重提或丢失。
- 新最佳沿用已有照片；低/同分不自动换图，用户可明确保存新贴纸到最佳楼。我的楼提供装饰、换图和撤回，照片变化不改楼体几何、成绩、名次和地块。
- 同一个buildTower在个人楼/结算/城市采样同一照片，按真实退台分段；远景缩略图、定位大图，资源释放并忽略迟到图片。玩家楼高仍对应真实层数。
- 沿用DB、增加BUCKET文件绑定；schema仅追加照片资产、楼体装饰和每日系统标记三张表。既有匿名cookie用于业务定位，不新增账号、跨端恢复、审核角色或图像备份/兼容导入工具。
- 客户端输出512×768 JPEG，服务端限量解码后只用像素重新编码，保存成品和缩略图；文件名/EXIF/GPS及照片字节不进城市JSON或公开Git。照片即时公开，过期/撤回新请求拒绝读取。
- 每次API先检查服务器北京时间日期，CAS和D1批处理按外键顺序清空全游戏表；重复/晚到调用不清除新一天数据。照片对象key含日期，文件任务可继续清理上一天对象。
- 手机和大屏检测午夜/新epoch后重新加载、重新匿名登记。客户端到期图片立即移除，手机继续自身视图，不恢复全城轮询。凌晨任务待发布后在同一Sites建立并记录实际回执。
