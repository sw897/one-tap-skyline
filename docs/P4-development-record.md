# P4 照片与每日游戏重置开发记录

2026-10-12 至 2026-10-13，Asia/Shanghai。状态：P4候选已部署为Sites7，供用户手工测试；正式验收未执行。每日00:00云任务已保存并启用，原生站点工具已成功调用并读回；首次定时运行及全量清空尚未验证。以下是审阅后的培训摘要，原文、日志及平台回执在仓库外私存。

## 真实要求与关键决定

用户批准照片保存后即时公开、匿名身份无需跨端恢复、照片最多24小时和草稿4小时、允许提前撤回；选择每天北京时间00:00清空全部照片/草稿。随后用户进一步要求00:00重置整个游戏，清空所有游戏数据。本实现清空正式和共享测试城市的成绩、排名、楼体、匿名玩家、局次、照片、草稿及限频记录，下一天重新登记。系统只保留防重复清空的技术标记；源码、Git和开发证据保留。

用户取消图像备份恢复、独立照片所有权/角色系统和兼容迁移工具，并要求本阶段不执行验收：先由用户手工测试，再进入下一阶段设计/实施，全部阶段完成后统一验收。保留必要类型检查、生产构建、发布与定时调用准备；没有将这些工作写成功能验收通过。

## 做了什么及修改原因

- 增加选图、拖动/缩放裁切、统一幕墙预览、跳过和公开确认；先提交成绩，成功后独立保存照片。失败可以在我的楼重试，已有成绩不因此重提或丢失。
- 新最佳沿用原照片；低/同分保留原图，可明确为最佳楼换图。我的楼提供装饰、换图、撤回；照片更新与楼体成绩/几何、排名、地块分开。
- 同一个TowerModel/buildTower按下部真实退台连续采样照片，个人楼/结算/城市共用立面。远景用缩略图、定位用大图；释放纹理、忽略迟到图片、到期移除。B/60秒及连击仅反馈保持原规则。
- 复用D1逻辑DB，增加R2逻辑BUCKET；仅追加照片资产、楼体装饰、每日标记三张表，原0000 SQL不修改。既有匿名cookie用于确定我的楼，没有新增账号、跨端恢复、审核后台或图像恢复/兼容导入工具。
- 手机输出512×768 JPEG，服务器限量解码后生成成品和128×192缩略图。读实际jpeg-js源码发现编码器可能保留解码出的EXIF/comments，改为只传像素/尺寸，避免带回元数据；这是代码修正，未做真实图片元数据验收。
- 换图/撤回以装饰版本处理重试与陈旧请求；静态复查补充撤回后实际版本检查，防止竞争时误报撤回成功。没有将构建通过当作并发功能通过。
- 每次游戏API先检查服务器北京时间日期，CAS和D1批处理按外键顺序清空全部游戏表；午夜后旧局不能继续提交。手机/大屏检测午夜或新epoch重新加载；用户继续只看自己的楼。
- 图片key含服务器日期，清理只删上一天及更早文件，晚到或重复任务保留新一天数据。照片最多保留到下一次午夜，草稿4小时与午夜取较早值；撤回先取消公开关联再删除文件，失败留待重试。
- 普通程序调用reset-due返回403，使用平台服务访问凭证仍为403，云网页读取也不可用。因此另作独立提交，增加Sites支持的MCP工具game_reset_status与reset_game_if_due，固定服务器日期、无强制/日期/城市参数。版本7上线后直接MCP HTTP仍403；平台工具稍后在会话中出现，通过原生通道完成只读、到期调用与读回。没有推断HTTP拦截的具体原因，也没有把连接成功写成全量清库通过。
