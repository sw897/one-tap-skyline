# P3 共享城市开发记录

2026-10-12，Asia/Shanghai。P3 实现候选，本地自动化通过；线上部署、同 DB 再部署和真实 iPhone + 电脑验收尚未执行。用户已批准修复计划审查问题并实施，确认免登录公开读取/匿名提交的推荐范围。安卓继续不安排。这里是审阅后的培训摘要，原始反馈、审批、日志、截图/视频、时序和数据库仅私存。

## 基线、关键决定与修复原因

- 起点：应用 `db2921b2a5adea660db93371483a764956e556df` / `p2-cutting-preview` / Sites 版本 3；文档基线 `c8e996bdd48e3f718b8688972a350aa2c11c4322`。B/60 秒、连击仅反馈与 P2 真机缺口保留。
- 计划审查实际复现了不同帧间隔导致楼体深度不同。先统一输入/绘制/暂停的整数微秒时钟，再以阶段锚点计算位置；客户端和服务端同事件的完整几何精确相等。不是用宽松误差隐藏差异。
- 接入原 Sites 项目的 Vinext 薄壳和 D1，保留同一个 Three.js 引擎/生成器。最初依赖安装遇到 Windows npm 路径解析问题，保留失败日志后用官方安装脚本和明确 npm CLI 路径恢复。
- 原 `index.html` 遮蔽全栈入口，导致首轮浏览器测试找不到挂载状态；移除旧入口后旧流程通过。原静态配置改为安全示例，正式同路径由服务器返回白名单。
- 共享触控测试发现结束那次触摸的点击偶尔误触新出现的“再来一局”。消耗同一落层手势的后续点击，下一次真实触摸仍可操作；补结算停留断言，保留原失败截图和视频。
- 真实城市、共享测试城市和内存练习明确隔离。玩家凭证仅 cookie，数据库存哈希；公共响应只含公开 ID、署名/层数/几何。固定 B/60 秒规则服务端复算；原子定稿/地块/最佳/revision、幂等回执、旧响应丢弃；不实施 P4 上传或 P5/P6。
