# P2 试玩与楼体成形优化实施计划

**状态：B 方案已实现为对比候选，首轮 iPhone 反馈更喜欢 B、无触控或闪动；P2 最终验收仍有缺项。** 更新于 2026-10-12，Asia/Shanghai。应用起点为 `c73e407` / `p1-core-visual.1` / Sites 版本 2。保留 V0.3 阶段路线和 V0.3.1 公开安全、真实留证约定；实际版本与结果见 [P2 开发记录](P2-development-record.md)。

体验方向已确定为**大众易上手**，沿用 **60 秒上限**，连击仅做反馈。用户暂不安排安卓试玩，安卓验证继续列为缺口，不作为本轮开工或有限范围交付的前置条件。

## 目标与当前问题

让新手继续用一指点击完成盖楼，同时更清楚地感受到落层、切割和堆叠，结算与城市中的作品具有更丰富的退台轮廓。是否更好看、是否影响上手难度，以实际对比试玩决定。

用户反馈：现有楼层只沿同一轴两端切割，楼体轮廓单调、不够美观。代码与此反馈相符：[楼体模型与裁切](../src/core/tower.ts)的每层只有 `x/width`，[游戏状态](../src/core/game.ts)只移动 `movingX`；[统一生成器](../src/render.ts)把所有楼层放在 `z=0`，进深固定为 `2.2`。现有断料已经会掉落、旋转，楼层也已有色差，并非尚无裁切表现。下面提出的是增强这些反馈，并评估是否扩展实际轮廓。

## 视觉表现与规则方案比较

| 方案 | 性质及改动 | 对操作难度与外形的影响 | 对现有实现的影响 |
| --- | --- | --- | --- |
| A 保持固定 X 轴，强化切割表现 | 视觉表现：断料采用当前楼层的实际颜色，沿真实切口短暂亮边；落料方向与切侧一致，强化短促落层反馈。统一生成器改善楼层边缘与立面明暗。 | 输入、容差和裁切结果不变；过程更清晰，但进深仍固定，无法解决前后方向没有退台的问题。 | 主要在 `render.ts`；复用现有断料和实例化楼层，不引入复杂物理、粒子系统或新依赖。基本几何模型不变。 |
| B 逐层自动交替 X/Z，加少量 A 的反馈（推荐） | 规则调整：第一层沿 X，第二层沿 Z，此后交替。每层只有一个活动轴，系统自动选择；点击时只裁掉该轴的超出部分。视觉表现只增强真实切口、同色断料与方向提示。 | 仍只需一指点击；需要观察两种移动方向，认知负担可能增加。宽度和进深分别收窄，真实楼体可在四侧形成退台。该效果取决于实际落点；全 Perfect 仍应是整齐直楼，不强造变化。 | `Layer` 扩展为 `x/z/width/depth`；裁切、移动状态、模拟样例、校验、统一渲染与测试需要适配。沿用矩形楼层、区间求交和现有 Three.js，不重做架构。 |
| C 放宽 Perfect 或降低速度 | 玩法参数调整，作为后续单变量试验。Perfect 仍仅对齐当前楼层，不回血、不加层。 | 通常有助于留下完整作品，具体效果待测；轮廓可能更整齐，也可能减少裁切变化。单独使用仍不能改变固定进深的限制。 | 现有配置已支持；参数试验必须记录真实值与结果，不与方向改动同时调整。 |
| D 斜切、自由旋转或自动补宽塑形 | 进一步改变裁切/补偿规则。 | 可产生更多形态，但判断更复杂；补宽还会改变“超出即裁掉”的含义。 | 斜切/自由旋转需要多边形求交；补宽需要新的补偿边界与验收。本轮不推荐，也不纳入最小方案。 |

## 推荐的最小方案与规则边界

推荐 **B：逐层自动交替 X/Z，配合真实切口亮边、同色断料和清楚的当前方向提示**。A 的代码改动最少；B 是能直接回应楼体轮廓问题的最小有效改动。先不增加倒角、屋顶生成、装饰系统、慢动作或镜头转向，避免把成形改动和大量视觉变量混在一起。

这把 V0.3/P1 的“固定 X 轴”扩展为“每层单轴、方向自动交替”，属于**已获用户批准的规则变更**。一指操作与逐层单轴保持，不能把它记为纯视觉修复。固定 X 基线用于对比，以配置选择候选，不在玩家流程增加模式选择。

拟采用的边界如下：

- 新楼层先继承上一层的矩形。非活动轴的位置与尺寸完全继承，活动轴求交；保留面积与实际断料面积之和等于移动层面积，不产生悬空扩宽。Perfect 只按活动轴当前尺寸的比例判定，随后对齐，无重叠则结束。
- X 基础宽度 `2.8`、Z 基础进深 `2.2` 不同。移动距离和速度按各自基础尺寸同比例换算，使两个方向的基础往返周期可比；不能直接照搬同一个世界坐标速度。固定斜视角保持，确认两种方向都能看清对齐；投影差异和真实手感仍须试玩验证。
- 60 秒、当前 Perfect 比例、落层时间及增速曲线先保持基线含义。方向改动比较完成后，若新手反馈需要，再单独比较速度或容差；不试 45 秒，不引入连击奖励、额外楼层或回血。
- 基座计 0，每次成功落层计 1；层高 `0.34`、基座高度 `0.42` 保持一致。游玩、结算与城市共用同一扩展后的 `TowerModel` 和生成器，楼高仍为 `0.42 + 层数 × 0.34`。不能只在城市把楼修饰成另一种轮廓。
- 首次入城、未破纪录保留完整原楼、新最佳用完整新局几何原地更新的语义保持。地块、颜色、署名稳定；同页旧楼与新最佳楼可有不同真实轮廓，不能拼接两局或把模拟状态说成持久化。

实现还需同步处理移动块、对齐轮廓、落层动画、断料朝向、镜头居中、窗格与幕墙预留位置，避免 Z 方向裁切后装饰漂浮或切掉后重现。旧模拟样例可按 `z=0`、固定进深读入新的内存模型；这是本阶段模型适配，真实身份、共享数据迁移仍留在 P3，上传和文件迁移留在 P4。

## 审核后的实施顺序

| 顺序 | 工作 | 输出与决定依据 |
| --- | --- | --- |
| 1 固定比较基线 | 保留当前应用 commit/tag、Sites 版本 2 和完整默认配置；记录可用 iPhone 的型号、系统、浏览器。先复核主要流程及已修复的闪动。 | 基线实录、原楼模型与测试环境。无法取得的设备信息或流程写未记录；严重触控、几何或结算问题先处理。 |
| 2 扩展统一模型 | 以固定 X 与自动交替两种候选验证 X/Z 两侧裁切、非活动轴继承、面积守恒、Perfect、漏放、层数和高度；适配模拟样例与完整楼替换。 | 核心回归和可复现输入。只在几何成立后进入视觉比较。 |
| 3 最小视觉适配 | 共用生成器适配逐层进深；补当前方向轮廓、切口短亮边、同色断料。检查窗格、贴纸预留、完整结算和城市原地增长。 | 同一局游玩/结算/城市的截图、模型对应及录屏。新视觉效果不得改变裁切结果。 |
| 4 小样本试玩 | 先由用户在现有 iPhone 比较固定 X 与交替方案，各建议 3 局、交换顺序。两种候选采用同一视觉反馈，配置只差方向规则；原版与视觉增强的效果另作比较。记录理解、误触、结束原因、层数、实际时长、轮廓偏好和是否愿意重玩。若方便，再增加 3–5 名新手。 | 优先确认“是否更好看、是否仍容易操作”。单人结果注明初步；不据小样本宣称大众难度已定型。 |
| 5 有依据地调参及回归 | 若方向变化造成判断困难，先处理方向提示；速度 `2.7` 与候选 `2.2`、Perfect `3.5%` 与候选 `5%` 可分轮单变量比较，其余保持一致。回归暂停、连点、旋转、三种模拟入城；iPhone 连续游玩约 5 分钟记录卡顿/帧时序与发热反馈。 | 候选值尚未实测；没有改善证据则保留基线。帧率测量不到写未验证。安卓暂不执行，尺寸模拟仍单独标注。 |
| 6 交付与归档 | 用户选定方案和参数后，完成提交及 `p2-playtest` tag，从同一提交构建并保存 Sites 新版本，在现有公开范围核实部署及免登录访问。 | 真实 commit/tag/部署版本、测试与缺项、原始私有证据、经审阅培训摘要及会话同步回执。P3 仍需另行讨论。 |

## 验收方式与未验证项

| 验收项 | 通过依据 |
| --- | --- |
| 裁切正确 | X/Z 正负侧、Perfect 边界、贴边/无交叠、极窄层与非法值均有实际回归；非活动轴不变，断料位置/尺寸和面积守恒正确。暂停、输入锁、计时与连击不加层通过。 |
| 三端一致 | 相同模型在三种视图的每层位置、宽度、进深和高度一致；例如 12 层为 `4.50`，26 层为 `9.26`。幕墙预留贴合实际楼层，装饰不扩张可得分面积。 |
| 三种入城情景 | 自动化检查首次、低于/等于最佳不变、新最佳完整替换且原地增长；可用 iPhone 实际走完整流程，保存证据。真机缺项不能用自动化结果覆盖。 |
| 新手与美观 | 同配置的固定 X/交替对比实录与反馈说明方向是否看得懂、点击是否仍自然、完成轮廓是否更受偏好。由用户选择候选；层数增加本身不是美观或易用通过的证明。 |
| 手机与性能 | 以实际可用 iPhone 的结果验收，型号/系统/浏览器明确，检查旋转、前后台、完整结算和重复开局。安卓继续标未验证且暂不安排；不宣称覆盖全部手机。性能有测量或明确缺项。 |
| 发布与留证 | public 推送前审查实际提交、文件、历史对象与 tag；应用与 Sites 版本对应，实际免登录访问可追溯。原始反馈/日志/媒体私存，公开材料先审阅，同步后读回。 |

交替方案代码、本地测试及实际浏览器截图/录屏已形成，真实试玩数据尚未取得。新结果见 [P2 开发记录](P2-development-record.md)；[P1 开发过程记录](P1-development-record.md)与 [计划修订记录](P2-planning-record.md)保持历史状态，安卓、完整真机流程及性能缺口仍未被自动化结果覆盖。

## 用户首轮试玩

1. 用户已选择 B，完成候选后先由本人在 iPhone 对比固定方向与逐层换向；建议各 3 局，用同一浏览器、保持默认参数，反馈方向理解、误触和成品偏好。
2. 机型、系统、浏览器与实际问题随反馈记录。少量新手与安卓不在本轮安排；安卓缺口继续保留，60 秒、大众易上手和连击仅反馈已经确定。

B 的开工依据是用户在开发会话的直接批准；归档与同步不构成进一步范围授权。最终参数与 `p2-playtest` 阶段完成等待真实试玩选择。本计划不实现 P3 身份/共享排行榜/真实数据迁移、P4 上传/文件迁移、P5 完整大屏互动或 P6 Docker/SSH。
