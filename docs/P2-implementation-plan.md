# P2 试玩与手感优化实施计划

**状态：待用户审核，尚未实施。** 2026-10-12，Asia/Shanghai。保留 V0.3 产品与阶段路线、V0.3.1 公开安全和留证约定。起点是已发布的 P1 应用 `c73e407` / `p1-core-visual.1` / Sites 版本 2。

## 目标

让第一次玩的参与者能理解点击和裁切，结束后看清自己的作品，并愿意再玩一局。通过真实手机和少量实际试玩，选择公平、易理解的候选参数，同时检查触控、镜头、结算节奏和性能。P1 的技术测试已通过，难度、实际局时长和重玩意愿尚无系统试玩数据。

## 范围与规则

P2 调整单局上限、移动速度及递增、Perfect 容差、连击提示、落层与镜头时长，以及必要的触控、布局和性能问题。继续使用同一楼体、同一层高和本页内存模拟城市；署名在结算后填写，贴纸仍只保留位置与跳过入口。

保持一成功楼层计 1 层、基座计 0、区间裁切、未破纪录原楼不变、新最佳用完整新局几何原地更新。连击继续只做反馈；回血或奖励楼层属于另行审核的规则变更。本计划不实现真实排名、跨设备身份、云端持久化、上传、大屏街区轮播或 Docker/SSH；对应 P3、P4、P5、P6。城市与榜单持续标为模拟数据。

## 实施顺序

| 顺序 | 审核后实施的工作 | 输出和停止条件 |
| --- | --- | --- |
| 1 补齐基准验收 | 固定 Sites 版本 2，真实 iPhone Safari 和安卓 Chrome 检查触控、快速连点、暂停、旋转、完整结算及三种模拟入城情景。记录机型、系统、浏览器、网络和版本；复核已修复的闪动。 | 两机实际反馈或实录；受阻项目写明原因。严重触控、成绩或楼体问题先修复，暂不调难度。 |
| 2 原参数试玩 | 建议邀请 3–5 名不同熟练程度的参与者，先各玩 3 局，首局不口头教学。用测试编号记录完整配置、实际时长、层数、结束原因、Perfect/误触观察、规则理解和重玩意愿。 | 原参数基线和问题排序。若只能单人试玩，保留为初步反馈，不宣称最终手感已验证。 |
| 3 少量候选比较 | 每轮只改变一个主变量、最多两套配置，同一批人交换先后顺序。先比速度，再视问题比 Perfect、时长，最后调镜头和结算节奏；优先解决误解与操作问题。 | 调整前后对比、选择理由及被放弃的候选。没有改善证据就保留原值。 |
| 4 手机与性能回归 | 每次影响规则或主要画面后跑相关核心/浏览器回归；两机连续玩约 5 分钟，检查前后台、旋转、重复开局、加载和结算，记录帧时序、卡顿和发热反馈。 | 性能基线及变化。建议以代表性设备平均可见帧率至少 30 fps 为初步目标；先测量再确认门槛，测不到则标未验证。 |
| 5 阶段交付 | 选定候选配置，完成两机复核、提交与 `p2-playtest` tag；从同一提交构建，保存 Sites 新版本并验证现有公开受众及未登录访问。 | 参数说明、回归结果、实际链接、截图/实录、私有台账与培训摘要。P3 是否启动另行确认。 |

## 候选参数的起点

P1 现状：上限 60 秒，初速 2.7，每层增速 0.035，Perfect 为当前宽度的 3.5%，连击提示阈值 3 次，落层 0.24 秒，镜头 1.15 秒，城市增长 1.7 秒。参数均保持可调。

例如第一轮只比较初速 2.7 与候选 2.2，其余保持相同；若反馈指向 Perfect 太难，再单独比较 3.5% 与候选 5%。时长可比较 60 与 45 秒。**这些是待审的试验起点，尚未执行或证明更好；实际局时长可能因失误早于上限。** P1 自动化用过的 180 秒和 12% 容差只用于稳定回放，不作为真人配置。

## 验收方式

| 验收项 | 通过依据 |
| --- | --- |
| 新手理解与重玩 | 原始试玩表能说明谁无需口头教学完成首局、是否理解裁切和结束原因、是否愿意重玩；小样本写人数和限制，用户据对比确认最终候选。 |
| 规则与作品一致 | 裁切边界、连点、暂停与计时回归通过；12/26 层等数据在游玩、结算、城市中几何和高度一致，连击不产生虚拟层数。 |
| 三种入城情景 | 真实两机同页实际完成首次入城、低于或等于最佳不变、新最佳原地长高；保存完整原楼/新最佳几何与稳定地块、色彩、署名检查。 |
| 手机与性能 | 两机型号/版本明确，旋转、前后台、长一点的连续游玩无阻断问题；有性能测量或明确的缺项，不能用尺寸模拟替代。 |
| 发布与留证 | 源码/构建/Sites 版本能对应；public 推送前审查提交、文件、历史及 tag；实际未登录访问与截图、实录可追溯。原始资料在仓库外私存。 |

## 需要用户决定

1. **体验倾向**：建议大众易上手、先留下作品；或希望明显更有挑战。决定速度与容差优化方向。
2. **单局上限**：建议先以 60 秒作基线，再比较 45 秒；也可指定培训现场更短的参与窗口。
3. **试玩安排**：能否安排 3–5 名参与者和一台安卓手机？需要补 iPhone/安卓的型号与系统版本；也可先仅由用户试玩，结论标初步。
4. **连击边界**：建议继续只优化反馈。若希望回血或奖励，请先单独讨论规则；本计划不直接引入。

审核确认这些选择后才实施 P2。审批前只整理计划与记录，不改玩法、默认配置或已部署应用，不创建 `p2-playtest` tag。
