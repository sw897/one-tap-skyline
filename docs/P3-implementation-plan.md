# P3 共享排名与持续入城实施计划

2026-10-12，Asia/Shanghai。**待用户审核，尚未实施。** 保留 V0.3 阶段路线与 V0.3.1 公开安全/真实留证规则。应用起点为 `db2921b2a5adea660db93371483a764956e556df` / `p2-cutting-preview` / Sites 版本 3；[P2 收尾及验收缺项](P2-closeout.md)如实保留。

## 目标与范围

让同一浏览器再次访问仍认得自己的楼；iPhone 提交有效成绩后，另一台电脑刷新或等待更新能看到同一楼、真实排名与邻近目标。首次入城分配稳定地块；低于或等于最佳不改变原楼；新最佳用整局新几何在原地更新。成绩、地块和楼体在服务进程重启后保留。

沿用 B、60 秒、现有速度与 Perfect 参数、连击仅反馈。游戏/结算/城市共用 `TowerModel` 和生成器，层高 0.34、基座高度 0.42；零层不入城，不能拼接不同局楼层。P3 包含匿名身份、局次/最佳持久化、真实榜单/邻近目标、跨设备共享读取、防重复与基本滥用控制、结构化迁移验证。照片选择/上传/文件存储在 P4，街区轮播/最新动态与完整投屏流程在 P5，Docker/SSH 在 P6。

## 现有代码与推荐技术路线

当前 `temporaryId()` 每次加载重建身份，`MemoryCityRepository` 是同步内存接口，12 栋样例与自己的固定地块只适用于模拟；榜单仅取前 7 项。渲染器固定 4×4 地块。当前没有后端、数据库或真实历史玩家数据，不能把刷新重置说成持久化，也不能只将内存对象保存到浏览器作为共享服务。

推荐在同一 Git 仓库采用 **Sites 提供的 Vinext 全栈入口 + D1**。新增薄页面壳和 API，继续使用 TypeScript、Vite 体系、Three.js 与已有核心/生成器；把页面初始化改为可挂载/清理的客户端入口，验证监听器与画布生命周期。无需将游戏重写成 React 状态或维护两套引擎。独立 Worker ESM 简易模板只打包单个脚本，不能直接承载当前独立静态资产，因此不选作这次默认迁移路径。

本地模板要求 Node ≥22.13，本机已记录为 22.22.2；这是前置版本匹配，**全栈依赖安装、构建、D1 本地/线上连通与旧游戏回归尚未执行**。Sites 只读预检确认当前项目 owner/public、静态版本 3、无数据库绑定。待批准后先验证全栈兼容；保留既有 project ID、受众、源历史与游戏几何，按平台流程增加逻辑 `DB` 绑定，R2 留空。兼容失败时记录阻塞并复审，不能直接宣称已支持共享服务。

将存储实现封装在服务端仓储接口，前端改用异步 HTTP 适配；模拟仓储保留作明确标记的练习/测试模式。Sites 运行 D1，P6 可换适配器；迁移须导出/导入验证，不能宣称 D1 自动随 Docker 搬迁。D1 提供参数化查询与失败回滚的批处理，计划据此组合条件更新和唯一约束，避免“先查后写”并发覆盖。[D1 官方 API](https://developers.cloudflare.com/d1/worker-api/d1-database/)

## 身份、规则与数据边界

| 项目 | 推荐的最小行为 |
| --- | --- |
| 匿名身份 | 服务端签发不可猜测的游戏访客凭证，用同源 HttpOnly/Secure cookie 关联匿名玩家；建议有效期 30 天。刷新和服务重启保留自己的楼。不同浏览器/微信容器/设备是不同玩家；清除 cookie 后无法自动认领旧楼。电脑能读到手机楼，不等于认成同一玩家。先不增加登录或身份合并；若要求跨浏览器认领，需在 P3 追加恢复码/转移设计并重审。 |
| 公开展示 | 建议维持免登录读取，展示选填署名、层数和楼体；玩家可跳过署名，使用中性默认名。共享提交前清楚显示这些内容会出现在公共城市/榜单。访客凭证、内部身份映射、日志和联系方式不进入公开响应。真实数据受众/写入开放范围需用户确认，现有模拟发布授权不能充当真实榜单验收。 |
| 官方榜单 | 只接受服务端固定的 B/60 秒 ruleset。设置面板、固定 X 对比和任意 URL 参数用于明确标记的练习模式，不混入官方排名。活动显示名与可公开规则由运行时配置返回；额外字段和秘密值不进入客户端，公开默认仍为“城市天际线”。 |
| 局次 | 服务端创建 run ID，绑定匿名玩家、城市、ruleset 与开始时间；每位玩家只允许有限活跃局。提交包含有上限的点击/暂停时序，服务端复算层数、计时/输入锁、Perfect 和整局几何。客户端总分与任意楼体不能直接作为可信入城依据。 |
| 基本成绩可信度 | 共用纯规则模块并补可复算时序，校验规则版本、事件顺序/数量、60 秒上限、落层锁、尺寸和结束原因；拒绝伪造层数、改参数、他人局次与重复入城。浏览器提供的事件仍可能被脚本生成，此方案不保证识别人类操作，也不作为奖金赛事级防作弊承诺。 |
| 最佳局 | `(cityId, playerId)` 唯一楼、地块唯一、run ID 幂等。已提交局重试返回既有结果；并发较低成绩不能覆盖较高成绩。首次选定颜色/署名/地块，此后仅严格更高层数替换完整最佳局；平局不改变楼或排序时间。 |
| 名次与目标 | 建议仅按成功层数降序，平局并列名次（1、1、3）；同分显示顺序按先达到该最佳成绩、再按稳定公开楼 ID。Perfect/连击/耗时不破平局。返回个人名次、附近玩家与下一档更高成绩/至少需多少层超过；个人在前 7 名之外也能找到自己的楼。 |
| 数据隔离 | 真实城市从空库开始；原有 12 栋模拟楼不导入真实排行榜。模拟、开发测试、真实体验分开标记与隔离；数据库真实导出及局次原记录在仓库外私存，公开案例只用获审阅的脱敏结果。 |

最小数据结构：城市/活动及 ruleset 版本、匿名玩家与凭证映射、局次/验证状态、每人最佳楼和稳定地块、城市 revision。楼体保存完整 `x/z/width/depth`、基座/层高及 geometry schema 版本，成绩由验证后的层数派生。只在首次/新最佳等真实变化时增加城市 revision；同分/低分与重试不产生重复增长。

前端提交加入等待、成功、失败与重试状态；失败保留本局作品并显示“尚未共享”，不能提前播放成功入城。网络超时后以同一 run ID 查询/重试；不重复开新提交。进入城市立即拉取，前台城市视图建议每 3 秒查询 revision，有变才取完整数据；游戏中和后台停止城市轮询，恢复时刷新。P3 接入简单真实更新，不做逐帧观战。新最佳回到原地更新，服务端 snapshot 为最终依据。

人数假设待确认：建议按 **60 位玩家、20 个并发会话**做 P3 有界验收。将地块容量扩到至少 60（例如 8×8、保留公共区域），稳定分配、同镜头适配、个人定位与完整数据读取；超限明确拒绝新增楼，不能覆盖或漏掉既有楼。大规模街区分片/轮播归 P5，超过此假设先调整验收范围。

## 迁移与可维护性

P3 开始建立可追加的 schema migration、ruleset/geometry 版本与 JSON 导出格式；提交 schema-only SQL 及生成元数据，已应用迁移不改历史。测试种子与数据回填另走受控工具；不在请求内建表。失败发布可能已应用迁移，须检查真实库状态再修复；仅回滚 Worker 不等于回滚数据库。迁移原则依据平台存储说明与 [D1 官方迁移文档](https://developers.cloudflare.com/d1/reference/migrations/)。

用独立测试库演练导出→空库导入，比较玩家/局次/最佳局数量、成绩、完整几何、地块、revision 和 schema 版本；敏感身份映射的导出只私存。当前真实数据库为空，没有旧生产数据可迁移；模拟样例的旧模型转换可作测试，不能伪称生产迁移已成功。

结构化记录迁移与身份凭证迁移分别验证。同源切换后端可保留 cookie；P6 改域名时 cookie 不会随数据库自动迁移，须提供经审核的认领/迁移方式或明确重新建身份。上传对象与照片授权/删除/文件迁移由 P4 处理，P3 不创建 R2 或上传接口。

## 验收方式

| 验收项 | 实际通过依据与证据 |
| --- | --- |
| 裁切/三端回归 | 原 22 项及受影响浏览器流程真实重跑；服务端与客户端同事件复算一致。B、60 秒、连击、层数/高度与生成器一致，原闪动与旋转回归。 |
| 身份与三种入城 | iPhone 同浏览器刷新后同玩家同楼；首次、低/等分不变、新最佳完整替换。保存 run/楼 ID 的脱敏关联与真机实录；三个 iPhone 浏览器分别记录，不假定共享 cookie。 |
| 跨设备 | iPhone 提交，独立未登录电脑城市页刷新/下一次轮询看到同层数、几何、地块/颜色；新最佳原地更新，低分/重试不增长。记录实际传播时间；建议成功提交后前台 5 秒内可见，真实网络未达标按实际记录。 |
| 真实排名 | 至少构造 12/12/9 等有效测试局检查并列排名、低分不覆盖、个人在榜外、空榜与邻近目标。测试数据在专用库标明测试，不污染真实城市；任意客户端分数不能直接入榜。 |
| 重复/并发/滥用 | 同 run 多次重试只一条有效局/一次入城；同玩家并发 9/16/12 层最终为 16；多人首次提交地块不冲突。越权局次、改参数/几何/计时、过大请求、超频与满城均有真实拒绝记录。 |
| 持久性与恢复 | 本地停止/重启实际服务仍可读取原楼，线上 Worker 重新部署同 DB 后仍保留；各自记录。断网/超时显示未提交并可幂等恢复；单独验证迁移失败后的真实状态，不把部署重启说成数据库重启。 |
| 迁移 | 测试库导出/空库导入后数量、最佳引用、完整楼体及地块匹配；记录版本、校验和与局限，P6 实际 Docker 迁移仍未执行。 |
| 手机与容量 | iPhone + 电脑重复开局、旋转/前后台、完整结算与三种共享入城；60 人/20 并发按最终确认值执行，记录请求错误/响应时间和画布表现。真机性能有实测值或明确缺项；安卓不冒称通过。 |
| 发布与培训 | 实际应用 commit/tag 与保存/部署版本可对应，线上匿名与持久性另验；私有证据索引、脱敏公开摘要与策划同步读回齐全。没有真实执行就写未执行/受阻。 |

## 需要用户决定

1. **P2 收尾范围**：是否接受现有 B/60 秒基线作为有限范围的 P2 交付，并保留 [收尾记录](P2-closeout.md)列出的真机/性能缺项？确认后再形成 `p2-playtest`，不从一次文字偏好推断全量验收。
2. **身份**：推荐“免登录、同浏览器匿名持久身份”；跨浏览器/设备只共享读城，各算不同玩家。若必须认领同一栋楼，请明确，P3 增加身份恢复/转移设计后再实施。
3. **排名与规模**：推荐只按层数、同分并列，按 60 人/20 并发验收。是否采用，或提供实际人数/并发要求？
4. **真实公开范围**：推荐免登录公开读取选填署名/成绩/楼体，匿名玩家提交；是否仍允许任何知道链接的人参与写入，还是限制体验者？需确认真实数据范围再开放相应写入口；现有 Sites 版本 3 的模拟受众保持。
