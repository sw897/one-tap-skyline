## 目标与范围

手机仍一指盖楼、查看和装饰自己的楼；电脑只读大屏，明亮海岛、六区76地块、最多十区、自动巡游与手动接管、全屏三维、小字二维码、高楼榜保留。B/60秒、连击仅反馈、统一主体几何、严格个人最佳、层数并列排名、随机楼名及新高改名换图保持。默认公开读与匿名提交、照片显式保存后即时公开，允许跳过/撤回。

云端从新的空城开始，使用同一公开中性名称和运行时活动配置；不搬迁Sites的成绩/照片/匿名身份，不增加账号恢复、所有权角色、历史兼容迁移、图像备份恢复或运营后台。持久卷用于保留当日数据，容器或服务器重启不会主动清库；北京时间00:00仍清空全部游戏数据，草稿4小时失效且受午夜截止限制。

## 当前适配条件与推荐方案

本轮实际只读检查：本机Docker客户端/引擎29.8.2，Linux x86_64引擎可连接，Compose5.5.1可用，OpenSSH客户端存在；没有构建/运行项目容器或登录服务器。Sites仍active/public/owner/12，唯一原午夜任务启用。目标云服务器、域名、端口及资源未检查。

现有app路由直接导入cloudflare:workers，API使用D1/R2，start/preview启动本地Wrangler；现有构建输出需要服务器适配。推荐一套源码、单实例Node.js游戏服务、SQLite数据库和照片文件卷，Caddy提供同源HTTPS入口；保留Sites的构建目标作为开发路径。

| 部分 | P6实施方式 |
| --- | --- |
| 前端与楼体 | 共用src/main、core、render、city-scene与CSS；增加Docker前端入口/构建目标，复用现有浏览器挂载函数与静态资源，不复制整套源码。 |
| HTTP与配置 | Node入口把HTTP请求转为现有Request/Response业务调用；统一/api与/runtime-config.json。以批准的公网Origin处理同源校验、HTTPS及Secure cookie，避免反向代理内部地址影响提交。 |
| 数据库 | 增加最小SQLite适配层，复用现有SQL与业务；prepare/bind/first/all/run及meta.changes保持含义，batch必须单事务、失败回滚、返回原顺序。[D1 batch语义](https://developers.cloudflare.com/d1/worker-api/d1-database/#batch)是适配基准。驱动与镜像版本在Linux兼容检查后锁定。 |
| 照片 | 文件存储适配现有put/get/list/delete、图片/缩略图和过期语义；媒体仍由API检查状态后提供。数据库、照片放独立命名卷，避免随应用容器替换丢失。[Docker卷文档](https://docs.docker.com/engine/storage/volumes/)。 |
| 午夜任务 | Node服务独立定时触发现有北京时间日切/文件清理，复用幂等标记；启动与请求也补偿遗漏，保护新日数据与拒绝旧局。草稿到期文件也由无人访问时的维护循环清理，不依赖浏览器或Sites任务。 |
| Docker与HTTPS | Compose包含游戏服务和Caddy；固定构建输入、健康检查、自动重启、数据/证书卷及部署说明。运行时公开配置与凭据分开，真实值在仓库外；Caddy域名/TLS条件实际核对后启用。[Caddy HTTPS文档](https://caddyserver.com/docs/automatic-https)。 |

Node/SQLite运行适配尚未验证。现有SQL初始化脚本保持原历史，不引入旧数据搬迁工具。回退只针对兼容版本的代码/镜像；不恢复已删除的游戏数据或回写旧午夜状态。

## 实施顺序

1. 审核本计划后，完成最小Node入口、SQL事务/文件适配与Docker构建；检查现有配置、请求、cookie、照片响应和规则接口能够复用。出现平台兼容问题先修适配，不修改玩法来绕过。
2. 形成可复现本地Compose候选，完成必要编译、启动、健康检查和存储/定时任务开发检查；测试数据使用隔离的本地卷，保留真实日志。这个步骤不是完整阶段验收。
3. 用户提供目标服务器与域名后，只读盘点系统、CPU架构、磁盘、Docker/Compose、已有服务与80/443占用。部署范围具体后，在安全渠道接收SSH材料，实施明确目录内的部署、HTTPS和真实公网入口；记录实际URL或阻塞。
4. 交用户手工体验容器/公网版，修正实际反馈。现有Sites的受众、写入和午夜任务在切换决定确认前保持；不把Docker的新空城与Sites自动同步。
5. P6开发完成后安排P1至P6统一验收，修复失败并保留失败/复测证据。验收范围与缺口明确后，执行最终入口切换、归档部署材料和培训案例。

## 需要用户决定和提供

1. 云服务器与HTTPS入口：现有服务器系统/架构、CPU/内存、Docker状态、已有服务和准备使用的域名；这些非敏感信息可先提供。SSH私钥/密码在实际部署时经安全渠道提供，当前不需要发送凭据。
2. 最终入口切换：推荐云端验收后作为唯一对外试玩入口，Sites收回“仅本人”保留主要版本留证；旧Sites游戏数据完成到期清理后，按确认结果处理原午夜任务。是否采用此安排，由用户确认，规划不改变现有受众。
3. 统一验收配合时间：沿用iPhone与1920×1080 Chrome大屏，安排真实手机、扫码/投屏及一次实际午夜观察。无可用域名或服务器时先交本地容器候选，公网部分记录受阻。
